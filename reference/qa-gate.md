# 当前验收门

1. 来源：原件哈希/只读，必保留内容、事实类型、单位期间与待定责任明确。新原件替代旧原件时，记录用户提供关系，不冒称由本技能修复。
2. 生成：实际字体测量、语义选版、同级字阶一致、长文重排/拆页；检测失败应停止并指出对象，不吞错/删内容。
3. 机械：`check-story.py`（声明与算术）、`verify-native-pptx.py`（包/枚举）、`check-pptx.py`（表格/缓存/内嵌数据）、`check-content.py`（生成字段文字覆盖）。任何一项只覆盖其明示范围。包检查不等于完整 ECMA-376 schema 验证。
4. 视觉：实际交付 PPTX 渲染全部页；整套缩略图检查一致性，逐页看字体、折行、遮挡、留白、关系、标签、页码与来源。不得继承旧版“不截图、最多三分之一页、普通页/表格不目检”的限制。
5. 编辑：在命名应用中对有预留的代表框增字约 30%，保存关闭重开，再渲染检查。记录原/新字数、字号与框几何；这是有限样本，不是任意文本的保证。
6. 交付：注明应用版本、字体与未验证对象。替代渲染器不能证明 Windows PowerPoint/WPS 兼容。可编辑文本/形状、原生表格、带工作簿图表、图片分别说明，不笼统称“全部原生”。

历史 `.pptd` 的 qa.mjs、render-truth-scan.mjs 仅供旧项目诊断，不替代本门。不得通过它们绕开受支持的 UI 工具或运行旧凭据导出。
