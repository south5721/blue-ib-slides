# 版面几何：检查闸与修复决策规则

> 触发场景：历史 qa.mjs 报 `text_overflow_est` / `collision_overlap` / `whitespace_hole` / `uneven_columns` /
> `cramped_zone` / `panel_void` 时，按本文决策**怎么修**。相关 `geometry-scan` 检测器是历史外部工具，不随本包分发；
> 当前包内可用检查以 `qa.mjs` 与 `SKILL.md` 为准。**总原则：先判断缺陷属于「空位」还是「溢出/碰撞」还是「过紧」，
> 三类各有固定决策序，不许凭手感随机修。**
>
> **blue-ib 适配注（2026-10-19）**：本文自 institutional-slides 复制，决策序与阈值机制与设计无关、原样沿用；
> K 体系专有数字已改写——**左缘 x=45.2、内容宽 1351（45.2..1396.1）**（原 65/1314）；
> **本体系无固定侧栏契约**（无 K 的 252 恒宽 insight panel），涉及 252 面板的段落已删除或泛化，

## 1. 三类缺陷的决策序

### 1.1 空位类（whitespace_hole / panel_void / uneven_columns）：**先拉伸 → 后填充 → 禁塞字**

检出的空白不是「缺点东西」，是「既有东西没撑开」。决策顺序固定：

1. **先拉伸（首选）**：既有构件按比例放大，把版面撑满——
   - **行高上调**：文本行高 token 调到 **1.25–1.3**（楷体实测行高大于声明值；`1.11→1.28`、
     `1.13→1.25` 已在腾讯/翱捷两本 showcase deck 验证有效，为推荐值）
   - **图表加高/加宽**：图高不够就加高（主展区底缘应读到 ~680-700），图宽不够就撑满栏宽
     （栏宽按 layouts.md 分栏网格取——本体系无固定侧栏契约；图右缘到下一元素不许留 >150px 死带，`chart_right_gutter` 同族）
   - **卡片/图标尺度上调**：panel 底空时，条目行距、icon、卡片内边距按比例放大（路演「少而大」原则）
   - **双列底边对齐（uneven_columns 专用）**：**拉伸短列**对齐长列底边——不许把长列截短迁就
2. **后填充（次选，只许内容型构件）**：拉伸后仍填不满，补的是**论证层次**——对照表 / read-across
   侧栏 / 时间轴 / 敏感性表。填充物必须有信息增量，与页面论证链相关。
3. **禁塞字（红线）**：严禁塞长段落凑空白——`text_block_blob`（≥300 字）闸会拦；密度靠条数不靠
   长度（2026-09-14 用户定）。「面板下半空 → 把条目写长」是最典型的错误修法。

**反例 → 正例**：
- 反例：腾讯 p37/p39 表格底与脚注之间 780×120 / 540×180 空带（表末行收场太窄）。
  正例：表格行高调 1.28 + 表下补一行 read-across 对照行，底缘读到 ~680（golden-ref 内容页底缘普遍 680–730）。
- 反例：regress-ic-aapl p7 中右列（memory 表 + CFO 段）底 466 vs 左列底 676，差 210px（26%）。
  正例：memory 表行高放大 + CFO 段补一句对 FQ4 指引的敏感性注记，两列底边对齐到 ±15% 以内。
- 反例（禁塞字）：往要点面板空位里再塞一段长文 → 触发 `text_block_blob` 且条目退化。
  正例：panel 条目行距 6→10px、判断句与论证段间距放大，或把面板与左栏图表同比例放大。

### 1.2 溢出/碰撞类（text_overflow_est / collision_overlap）：**瘦身文本 → 调行高 → 扩框 → 减元素**

检出「估算行高 > 框高且压到邻居/容器/脚注区」或「字形框相接」时，按固定顺序修，**不许一上来就删内容**：

1. **先瘦身文本（≤2 行原则）**：每条 bullet/注释控制在 **2 行以内**。写之前先算，别等闸拦：
   `node scripts/text-geom.mjs --text "…" --width <框宽> --size <字号>`（与闸共用 em 宽表；
   折行触发阈 = 框宽 ×（CJK 1.06 / 拉丁 1.10））。
2. **再调行高**：声明 lineHeight 低于实测时上调到 **1.25–1.3**（楷体 1.3 / 英文 1.15 是估算地板，
   声明值低于地板等于给渲染器埋压行）。
3. **再扩框**：框高给到估算高（首行 ×1.2 + 后续行 ×行高因子），或加宽框减少折行。
   表格 cell 压发丝线：行高上调 + cell 框高加 4–8px。
4. **最后才减元素**：两条 bullet 并一条（信息不丢的前提下），不许直接删论证。
5. **字阶红线**：**不许把字号压到 14px 以下**解决溢出（信息地板 14px，铁律 9）——字阶是角色语义，
   不是排版旋钮。压字阶 = 把缺陷从「版面」转移到「字阶体系」，两闸都会拦。

**反例 → 正例**：
- 反例：腾讯 p15「第二引擎」bullet 区——`GPU 租赁 / MaaS / WorkBuddy / 国际云` 四条均估 2 行（36px）
  但框高只留 1 行（20.5px），第二行与下一条第一行互相贴上（四连压行）。
  正例：每条瘦身到 2 行内 + 行高 1.28 + 条目间距 8px；或框高给到 36px。
- 反例：asr-micro p11 卡片正文被 READ ACROSS 横带压切（b2-body 估 3 行 61px > 框 44px）。
  正例：正文瘦到 2 行（≤2 行原则）+ 卡片加高 20px。
- 反例：脚注 3 行从 724.1 起超界。正例：密集页脚注用密集档 `[45.2, 741.7, 1312, 34]`（常见缺陷表既有条目）。
- 反例：demo p2 `toc-msg-ab` 文本压到 guide panel 上（渲染残影可见）。
  正例：文本缩短到 panel 左栏内，或 panel 加宽到文本右缘之外 16px。

### 1.3 ~~过紧类（cramped_zone）~~ **已下线（2026-09-24 盘点：6 次命中大多裁决保留，同族表格节奏误伤率过高）**

原判定：同列异质元素连续 ≥3 处间距 <6px = 下半区堆叠过紧。**下线理由**：6 次命中大多被裁决保留
（同族表格节奏属豁免形态），闸的误伤率高于真缺陷率——保留它等于让每本 deck 背一笔无效裁决成本。
检测逻辑已从 geometry-scan.mjs 移除；同族节奏问题由 text_overflow_est / collision_overlap 兜底。

## 3. 阈值标定记录（准入三关的证据链，改阈值前先读）

**文本几何估算模型**（`estTextHeight`，与 overlap-scan.mjs 同源并修正三处过敏感）：
- 行高因子：**首行 ×1.2**（字形框），**后续行 ×（CJK 1.30 / 拉丁 1.15 地板，声明值更大取声明）**。
  行高因子只管行间——单行文本不吃 1.3（golden toc 18px 单行标题 18×1.3=23.4 vs 框 19.3 的误报根因）。
- 折行触发：`行数 = ceil(est宽 / (框宽 × K))`，**K = CJK 1.06 / 拉丁 1.10**。K 同时吸收 em 宽表
  对英文 ~5–10% 的系统性偏胖与词界折行损失。标定点：aapl p32（est/框=2.11，实渲 2 行）、
  腾讯 ever-b（CJK 1.15，实渲 2 行）、golden「Spend pool, TAM & SOM」（0.99，实渲 1 行）——
  一律 ×1.15（title_render_lines 的系数）会把前两例判反，故几何闸不用 1.15。
- **落点命中制**：估算高 > 框高 ×1.06+4 **且**溢出部分撞到（下方元素顶 / 容器底 / 脚注区顶）才报。
  无害溢出（落进空白）不报——golden 文本框贴内容高、溢出由下方留白吸收是合法形态
  （golden p17 note 溢出 10px 落空带；p23 注释声明底 728.7 字形底 722.3）。锚定方向：
  align 含 bottom 的元素（chrome-footnotes）溢出向**上**长，落点查上方元素底/容器顶。
- 字形框：单行文本（含 wrap:true 但估 1 行）宽按估算宽——声明框常比字形宽一截
  （demo p4 kicker 声明 431.6 字形 ~90，22px 越界是声明噪声）。

**whitespace_hole（多洞枚举升级，2026-09-23）**：
- 短边阈 300×150 → **短边 ≥120px**（用户 spec）：golden 列缝 40–60px 天然够不着；
  250×373 级列底差带可及。面积阈**沿用旧闸 7%/10%（两 tone 不动）**——不取「建议 8%」：
  mid 变异（330×270=7.6%）与 ASR p8 实案（7.6%）都坐在 7–8% 带，7% 是旧闸标定值且保有既有裁决记录。
- 触边 ≥2 窄条带豁免（IC min 边 <240 / 路演 <280）沿用旧闸；**豁免作用于整条空区**——
  内缩子矩形一并压掉，否则全宽底带被豁免后其子矩形以 touches=1 复活成 error（roadshow-strip-exempt 变异案）。
- 结构页豁免：封面/隔页/目录（L01/L02/L03 fixed 骨架，与 page_sparse 的 L03 豁免同构）。

**uneven_columns**：>15% 页高 warn / >30% error。语料：golden 列底差 max 96px、demo 74、
dogfood 62（<15% 天然静默）；regress-ic-aapl p7 210px（26%，真缺陷形态但 corpus 内存量）→
error 档定 30% 保 corpus 零 error（准入纪律：误伤比漏检更危险，error 档待存量裁决后下压）。

~~**cramped_zone**~~ **已下线（2026-09-24 盘点）**：6 次命中大多裁决保留（同族表格节奏属豁免形态），
误伤率高于真缺陷率。检测逻辑已从 geometry-scan.mjs 移除；同族节奏问题由 text_overflow_est /
collision_overlap 兜底。原标定记录：<6px × ≥3 连（不是 <8px）——golden p23 图+注释 7/7/7 是合法节奏下限。

**底带空洞（原 mainzone_bottom_gap 并入 whitespace_hole，2026-09-24 盘点）**：20 次命中相当比例裁决为
「呼吸区」保留，且与 whitespace_hole 检测维度重叠——底带空洞作为 hole 的一种位置标注，不再独立成闸。
tone 阈值沿用原闸：IC 底缘 <650 warn / <600 error；路演 <620 warn / <560 error。L05 方法论附录豁免。

**容器（panel）判定**：有填充矩形（面积 ≥20000、宽 ≤900、非全幅）且内含 ≥2 文本；
panel_void 要求 ≥3 文本。golden p11 map-tint-tr（地图 tint 底衬，内 1 文本）不是内容容器。
容器越界容差：底 +6px（golden stat-note 4.4px 属舍入噪声）、右 +16px（stat 条末格 13px 属 canonical）。

**三关验证（2026-09-23）**：corpus 18 本 0 error（golden-ref 0 新增 warn；新增 warn 14 条均截图核实）；

## 4. 渲染真值与行高机制（2026-09-23 hai 24p 跨平台溢案定案）

**缘起**：hai-robotics 24p 在几何闸与 qa.mjs 双绿、Rust 渲染绿、PowerPoint(Mac) 渲染绿的情况下，
用户在 PowerPoint 真实打开后 p10/p12/p13 出现大面积重叠。逐条证实/证伪：

- **根因①（验收渲染对象错了）——证实（流程级）**：skill 的 QA 此前把 Rust 预览器截图当验收依据，
  没有一道闸在「交付目标原生渲染器」上验收（AGENTS.md 早有铁律「Mac=QuickLook、Win=Word 本体」，
  但工作流未作硬闸）。Rust 绿 ≠ PowerPoint 绿 ≠ QuickLook 绿。
- **根因②（估算因子偏乐观）——证实，但是行高因子不是宽度因子**：实测 PowerPoint 导出 PDF 的
  逐词坐标（pdftotext -bbox），楷体行距 = **声明行高 × 字体自然行高**，而字体自然行高随平台漂移：
  **楷体 Mac ≈1.21em**（14px 声明 1.20 → 渲染 20.3pt=1.45em；16px 声明 1.13 → 22.1pt=1.38em）、
  **Windows/替代 ≈1.33em+**。同一 spcPct 在不同平台得到不同绝对行高——hai p13「客户复购率」kicker
  框高按 14×1.06 设计、楷体渲染行高 20.3pt，每行实际多吃 5.5pt，与「89%」相压 1pt（Mac）；
  在更宽的渲染器上相压 5pt+，即成片的「面板文本溢出面板下缘压标题区」。
  ⚠️ 副产物：**双值字体「Arial, 楷体」让英文文本的行高也被楷体自然行高驱动**
  （demo p26 实测英文 title 行距 23.0pt=1.44em，与 CJK 同高）。
- **根因③（文本框无 autofit 兜底）——证实**：pptx 里 0 个 normAutofit/spAutoFit，溢出 100% 可见。

**naturalRef 标定值（Mac PowerPoint 实测，逐词测量）**：

| 字体 | 自然行高 | 测量方式 |
|---|---|---|
| 楷体（含「Arial, 楷体」双值中的 CJK 驱动） | **1.21em** | 多行 CJK 文本行距/（字号×spcPct），14px→1.19、16px→1.22、18px→1.29（取 14px 主导值） |
| Georgia（含「Georgia, 楷体」双值） | **1.16em**（双值时 CJK 驱动 1.21） | 单行大数字字形高/（字号×spcPct），28px 题 31.8pt=1.14em |
| Arial（纯拉丁） | **1.15em** | 标准值（Arial 跨平台度量稳定） |

估算模型 lhEff 已由 `max(声明, 1.30)` 改为 **声明 × naturalRef**（geometry-scan.mjs `estTextHeight`，
naturalRef 按 fontFamily 是否含 CJK 字体判定，不按文本内容）。

**渲染真值闸（render-truth-scan.mjs）**：pptx → 交付目标原生渲染器（PowerPoint AppleScript 导出 PDF，
降级 qlmanage 首页 LIMITED，都没有报 BLOCKED 不许 Rust 顶替）→ pdftoppm PNG（目视件）+
pdftotext -bbox（文本坐标），比对声明几何（pptx XML）与渲染真值：
`rendered_overflow`（渲染底压进别人字形区，error）/ `rendered_tight`（间隙 <4pt 零 slack，warn）/
`rendered_collision`（渲染包围盒相交 >30%，error）/ `panel_breach`（越出 panel 边界，error）/
`footnote_intrusion`（压进脚注区，warn）。hai 24p 实测：1 条真重叠（89% 卡压 1pt）+ 7 条临界。

**归属规则标定（渲染词 → 声明帧）**：两级——① 强匹配（帧声明框包含词中心且声明文本包含词文本）；
② 溢出兜底（声明文本包含词文本、**词 cx 在帧 x 域内即同列**、距框 y 域 ≤30pt）。
⚠️ 两个已踩的坑：不能按中心点归属（密集堆叠时溢出文本被错归到下一帧，把「自己的行高」误判成
「与别人的重叠」——ASR p5 bullet 2pt 真重叠被算成 18pt）；兜底必须要求 x 包含（通用词 CAGR/SoC/2026E
在多列文本里都出现，只按 y 距离会把左列的词归到中列——ASR p5「CAGR」x=213 被归到 x=541 的帧，
extent 顶被抬到 340，造出 75%/16.7pt 假碰撞）。

**渲染链生命周期**：AppleScript `with timeout of 600 seconds`，先试保持存活（批量快），失败则
kill 后以 quit 模式重试一次——-1712 AppleEvent 超时多为冷启动慢，-9074 多为残留模态，kill 可清。

**spcPts（行高绝对化，已落地 polish-pptx.mjs，默认开启）**：把 `<a:lnSpc><a:spcPct>` 改写为
`<a:spcPts>` = 字号 × spcPct 比例 × naturalRef，让所有平台渲染出与 Mac 一致的绝对行高。
hai 24p 全 deck 逐词对比：spcPts 版与原渲染中位偏差 0.5–0.7pt、max 4pt（逐词位置匹配），
verify-pptx 13/13 通过。⚠️ 重写必须用回调 offset 定位（相同 pct 的条目用 indexOf 会全取到第一条的 sz）。

**normAutofit 评估（不用）**：实测注入 `fontScale="90000" lnSpcReduction="10000"` 后，溢出的 14px 标签
被自动缩到 12.6px 装下——但 ① 字号不可控漂移（12.6px 不在 12/14/16/18/28 偶数字阶，破铁律 9）；
② 逐框各自缩（同页同角色字号不一致）；③ WPS/QuickLook 可能不执行（守不住验收环境）。
spAutoFit 会推挤邻元素，更不可用。**兜底的正解是 render-truth 闸 + 保守估算 + spcPts，不是缩字。**

**三关（渲染真值相关）**：corpus 18 本 0 error（demo p26 两条 2 行标题 4.2px 真重叠，按决策序
扩框下移 desc 清零，属缺陷闭环第三步）；synthesis 66 变异 0 误报；mutation 107/107。

## 5. 常用构件文本预算表（内容卡阶段按预算写，不是闸）

> 每行字符数 = 框宽 /（K × 字宽 em × 字号），K = CJK 1.06 / 拉丁 1.10；

**用法（三条就够）**：
- **bullet ≤2 行**：按框宽查「CJK 字/行」×2 封顶。14px/200px 框一条 ≤26 字（CJK）/46 字（英文）；
  16px/300px 框一条 ≤34 字（CJK）/60 字（英文）。预检：`node scripts/text-metrics.mjs --check "文本" --width <框宽> --size <字号> --cjk`。
- **面板条目按行数预算**：按面板实际净高查「最多行」两列——判断句（16px bold 1–2 行）+ 论证
  （14px 2–3 行）合计 ≤6 行是安全水位，逼近上限就瘦身（本体系无固定侧栏契约，面板宽度按 layouts.md 网格）。
- **表格 cell 行高预算**：cell 框高 = 行数 × 每行高度（14px 21.2 / 16px 24.2）+ 上下各 4px 余量，
  不够就加高 cell 或减字，不许把行高压到 1.13 以下凑。
