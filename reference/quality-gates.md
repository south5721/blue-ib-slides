# 内容、可编辑性与视觉验收

按任务风险选择检查深度；小改稿不强制写完整机器页纲。任何静态通过都不能替代逐页视觉检查。

## 1. 页纲与数字勾稽

长稿、议程、利润桥或数据密集稿可用 `check-story.py` 检查结构化页纲：

```text
python "<SKILL_DIR>/scripts/check-story.py" "<任务目录>/story.json"
```

可加 `--out "<新检查结果.json>"`；既有文件不覆盖。退出码：`0` 为未发现结构性错误，`1` 为检验失败，`2` 为读取或输出失败。

最小结构为 `title` 和非空 `slides`；每页须有 `id`、`title`、`layout`、`message`。`message` 是本页核心信息或目的，不要求每页都写结论句。`rhythm` 为可选自由文本，不强制“密—疏—密”模式。示例仅用于结构演示：

```json
{
  "title": "示例会议方案",
  "expected_slides": 2,
  "sources": [
    {"id": "s1", "locator": "示例原稿.pptx，第2页"},
    {"id": "s2", "locator": "用户确认的议程调整"}
  ],
  "required_content": [
    {"id": "agenda", "description": "保留全部议程与总时长"}
  ],
  "slides": [
    {
      "id": "p1",
      "title": "会议目标",
      "layout": "cover",
      "message": "说明本次会议目的",
      "claims": [
        {"text": "建议设置成果发布环节", "kind": "proposal"}
      ]
    },
    {
      "id": "p2",
      "title": "会议议程",
      "layout": "native-table",
      "message": "议程分两段，总计60分钟",
      "rhythm": "信息密集",
      "covers": ["agenda"],
      "claims": [
        {"text": "会议总时长为60分钟", "kind": "fact", "source_ids": ["s2"]}
      ],
      "data": [
        {"label": "总时长", "value": 60, "unit": "分钟", "source_ids": ["s2"]}
      ]
    }
  ],
  "arithmetic_checks": [
    {"type": "agenda", "values": [25, 35], "total": 60, "tolerance": 0},
    {"type": "bridge", "start": "100.0", "deltas": ["12.0", "-3.0"], "end": "109.0"}
  ]
}
```

检查范围：

- 页数、必填字段、重复 ID、必保留内容是否分配到页面。
- `claims` 中缺少正文、事实或推断未标注来源、引用不存在的来源时失败。`kind` 为 `fact`、`inference`、`proposal` 或 `assumption`；后两类可以无来源，但必须真实地属于建议或假设，不可借此绕过事实核验。
- `data` 中缺数值、单位或来源时失败。数值接受有限数字或十进制字符串；时间、统计口径、实际／预测等信息按需要补充在记录或页上，不由脚本推断。
- `bridge` 检查 `start + sum(deltas) = end`；`agenda` 和 `sum` 检查 `sum(values) = total`。用十进制定点运算，默认容差 `0.000001`，可显式调整，议程不接受负时长。
- 连续三页相同版式仅提示复核，不强制更换，不因告警单独判失败。

脚本只检查已声明的字段，不读取来源正文、不判断来源是否支持论点、不自动发现未登记在 `claims/data` 中的数字，也不检查算术输入是否与成品对象一致。必须由作者逐项核对来源和成品，不能把“清单通过”写成“事实全部核验”。

## 2. 生成与原生编辑能力

当前本机入口为 `build-native.py`，调用原生生成器、`verify-native-pptx.py`、`check-pptx.py` 与 `check-content.py`。可传 `--story` 接入本文件的来源/勾稽检查。原 v2 的 artifact-tool/PPTD 导出器未作为当前执行入口。

分别记录实际达到的编辑级别：

- 文本、形状及连接线：可选择、可改文字或几何；组合图需能解组修改。
- 表格：`a:tbl` 原生表格才支持单元格及行列操作；文本与矩形组合不称为原生表格。
- 数据图表：原生图表结构、系列与内嵌工作簿均正确，才能说明支持编辑数据；形状拼出的柱形或曲线只是图解。
- 图片：保留为图片，不声称其中内容原生可编辑。

包结构检查只能证明相应对象存在；关键图表应在可用的原生办公软件中抽查“编辑数据”，或明确披露仅完成结构和数据勾稽，未做该交互验证。

## 3. 逐页视觉核验

渲染全部页面，检查裁切、溢出、重叠、字体替换、字号层级、标签、连线、页码、图片比例和表格几何。修改后重检受影响页。不可用静态字符宽度估算代替渲染。

重要数字、议程时长、标题与正文、单位和时期需对照原材料核验。保持源文件只读；交付前确认修改范围、必保留内容及待补充事项均被满足。无渲染条件或部分对象无法验证时，说明具体未验证项，不宣称全部通过。
